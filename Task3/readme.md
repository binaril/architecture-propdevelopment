# Требования к внешним интеграциям для новых сервисов умного доступа

## 1. Требования к безопасности

### Общие требования
- Соответствие нормативным требованиям
- Логирование и аудит. Все действия с данными должны журналироваться (время, действие, данные, результат)
- Ротация ключей шифрования

### API Gateway
- Внедрить централизованный API Gateway для контроля доступа к внутренним и внешним API, мониторинга и аудита передаваемых данных

## Политика безопасности
- Разработать и внедрить единую политику безопасности для всех партнерских API, ограничив доступ к определённым категориям данных.

### Шифрование данных
- Обмен данными между сервисом `smart-service` и внешними системами, должен быть зашифрован с использованием протокола TLS (Transport Layer Security) версии 1.3 или выше.
- Обмен данными между сервисом `smart-service` и хранилищем `smart-service-db` через JDBC должен быть зашифрован с использованием протокола TLS версии 1.3 или выше
- Резервные копии должны быть зашифрованы

### Токенизация данных
- При взаимодействии с партнерскими API заменять персональные и биометрические данные токенами, для предотвращения утечки
- Токены генерируются внутренней системой `smart-service` перед передачей во внешние системы, хранятся в `smart-service-db` в зашифрованном виде


### Соответствие нормативным требованиям

## 2. Протоколы аутентификации и авторизации

- Основной протокол OAuth 2.0 
- Авторизация от имени пользователя с использованием OpenID Connect (OIDC)
- Использование JWT токена для передачи контекста безопасности. Срок действия токена должен быть ограничен

## 3. Организация взаимодействия между системами

- Запросы от мобильного приложения для управления умным домом API Gateway перенаправляет в сервис `smart-service`
- `smart-service` выступает в роли адаптера для внешних систем.
- Допустимые протоколы взаимодействия **REST API**, **WebSocket**
